# Tabiji マネタイズ・マーケティング戦略

作成日: 2026-07-07 / ステータス: 調査・検討メモ（`docs/02_specification/ai-plan-generation.md` §7 の発展版）

## 1. 前提・制約

- **個人情報を扱いたくない**。ユーザーの個人情報を持たないだけでなく，運営者自身の氏名・住所公開（特商法表記）も避けたい
- **赤字NG**。固定費ゼロ・従量コストに天井がある構造のみ採用する
- 個人開発。運用に人手をかけられない（返金対応・問い合わせが重いモデルは不利）

### 構造的な整理（これが結論の骨格）

誰から・どうお金をもらうかで，法的負担が3段階に分かれる。

| 型 | 例 | 特商法表記（氏名・住所公開） | 資金決済法 | 決済実装 |
|---|---|---|---|---|
| **広告型**（広告主から） | アフィリエイト | **不要** | 対象外 | 不要 |
| **代売型**（プラットフォーム経由） | MCPマーケットプレイス | 不要の可能性高（規約要確認） | プラットフォーム側 | 不要 |
| **直販型**（ユーザーから直接） | プレミアム課金・AIクレジット・チャージ | **必要** | チャージ型は該当し得る | Stripe等が必要 |

→ 「個人情報を出したくない」制約下では，**広告型 → 代売型 → 直販型** の順に筋が良い。

## 2. 調査結果（2026-07時点）

### 2.0 前提: MCPのコスト構造はアプリ内AIと正反対

MCPサーバーは**LLMを一切呼ばない**。ただの「ツール置き場」で，中身は既存の `createShiori` と同じDB書き込み処理。プランを考える頭脳は**ユーザー側のClaude**（その人のサブスクやAPIキー）なので，**AI使用料はユーザー持ち**になる。

| | AI費用の負担 | 運営者のコスト |
|---|---|---|
| アプリ内AI（Phase 1） | **運営者**（トークン代を払って誰でも使える） | AI API料金 + 実行環境 |
| MCPサーバー | **ユーザー**（自分のAIを持ち込む） | DB書き込みと関数実行のみ ≒ ¥0 |

- つまりMCPは「ずっと赤字」ではなくむしろ逆で，**原価ほぼゼロで提供できるAI連携**。「赤字は嫌」に一番優しい形
- 守りが必要なのはAI費用対策ではなく，しおり乱造スパムへのレート制限（DB容量の話）のみ
- 副産物: ユーザー側のClaudeは自前でWeb検索できるため，「営業時間を確かめてから登録して」が**運営者の実装ゼロで成立**する（アプリ内AIでは Phase 4 の課題だったもの）

### 2.1 MCPマーケットプレイス

「MCP版アプリストア」。開発者はサーバーを作って出品するだけで，決済・税務・ホスティングをプラットフォームが肩代わりする。

| プラットフォーム | 取り分 | 肩代わり範囲 | 備考 |
|---|---|---|---|
| **MCPize**（2026年初登場） | 80〜85% | ホスティング・決済・**税務コンプライアンス**・サポート。Stripe Connect 経由で月次払い | 課金モデルはサブスク/回数課金/フリーミアム等を選択可。新興のため事業継続性は未知数 |
| **Apify**（実績あり） | 80%（マイナス実行コスト） | 決済・税務・請求書。`Actor.charge()` を呼ぶだけのイベント課金 | 元はスクレイパー市場。MCP対応は2025年末〜。老舗で支払い実績が長い |

- 販売主体（seller of record）がプラットフォーム側になるかは両者とも規約の明文確認が必要。ただし「税務・請求をプラットフォームが処理し，開発者はStripe Connectで受け取る」構造は App Store と同型で，**自前の特商法表記なしで課金を試せる可能性が高い**
- 注意: Tabiji の MCP はDB（Neon）と繋がる必要がある。マーケットプレイスにホスティングされる場合，MCPサーバー → Tabiji のAPI を叩く2段構成になる（実装は増えるが可能）

### 2.2 マイクロペイメント（Cloudflare / x402）

- Cloudflare が **Monetization Gateway** を発表（2026-07-01）。API・データ・**MCPツール呼び出し**に対して x402 プロトコル（HTTP 402 + ステーブルコイン）で1回数円の課金を，決済実装なしで挟める仕組み。現在は**ウェイトリストのみ**で料金・時期未公表
- x402 は Coinbase 主導で初年度1.69億決済と急成長中。AWS もエッジ対応を発表
- ただし決済手段が USDC 等の暗号資産のため，**日本の個人には税務・会計処理が重い**。日本円で受け取る簡単な道はまだない
- 評価: **本命候補だが時期尚早。ウォッチ枠**（半年〜1年後に再評価）

### 2.3 旅行アフィリエイト

| プログラム | 料率 | 備考 |
|---|---|---|
| 楽天トラベル（楽天アフィリエイト） | 約1%（**1予約あたりの上限なし**） | 楽天市場と違い1,000円上限がないため宿泊単価が活きる。個人サイトOK・審査軽い |
| じゃらん（ASP経由） | 1〜2% | バリューコマース等のASP登録が必要 |
| Booking.com | — | 日本の個人アフィリエイトは現在実質利用不可 |
| アソビュー・klook等（体験系，ASP経由） | 数%帯 | 行程の「アクティビティ」枠と相性が良い。要ASP審査 |

- 法的負担: 特商法・資金決済法とも対象外。必要なのは**ステマ規制（景表法）対応の「PR」表記**のみ
- Tabijiとの相性が構造的に良い: **AIプラン生成の瞬間 = まさに宿・アクティビティを予約する直前**。生成された行程の宿泊・施設カードに予約リンクを添えるのは，広告ではなく機能として自然

## 3. マネタイズ候補の比較

| 候補 | 収益性 | 実装コスト | 法的負担 | 個人情報 | Tabijiとの筋 |
|---|---|---|---|---|---|
| **A. 旅行アフィリエイト** | 小〜中（単価¥300〜1,000/成約） | 小（リンク生成のみ） | ほぼゼロ（PR表記のみ） | ゼロ | ◎ 予約直前の導線そのもの |
| **B. MCPマーケットプレイス課金** | 小（市場黎明期） | 中（MCP + 2段構成） | 小（プラットフォーム肩代わり） | ゼロ | ○ 話題性は最大 |
| **C. プレミアムしおり（`isPremium` 買い切り）** | 中（¥300/冊等） | 中（Stripe + 機能開発） | **特商法表記が必要** | Stripe側に購入者情報 | ○ 旅行は単発イベントなので買い切りが合う（サブスクより） |
| **D. AIクレジット・チャージ制** | 中 | 中〜大 | **特商法 + 資金決済法（6ヶ月失効設計）** | 同上 | △ AI原価が無料枠なら売る理由が薄い |
| **E. x402マイクロペイメント** | 未知数 | 小（Gateway任せ） | 暗号資産の税務が重い | ゼロ | ○ 時期尚早 |
| **F. ディスプレイ広告（AdSense等）** | 極小 | 小 | 小 | Cookie同意等 | ✗ しおりの世界観を毀損。非推奨 |

## 4. 推奨戦略 — 段階ロードマップ

**「無料で配って，予約で稼ぐ」を軸に，直販は最後まで温存する。**

### Stage 0（現行計画）: AI機能を無料で出す

- Gemini 無料枠 + IP制限（ai-plan-generation.md Phase 1）。コストゼロで需要検証

### Stage 1: アフィリエイト導入 ← 最初の収益化

**前提: ホスティング移行が必要。** Vercel Hobby はアフィリエイトを含む広告掲載が禁止のため，導入と同時に Cloudflare Workers 無料プラン（商用利用OK）へ移行する。詳細は `hosting.md` 参照。

- 楽天アフィリエイトに登録（審査軽・個人OK）
- AIプラン生成時，宿泊・主要スポットのカードに「楽天トラベルで見る」リンクを付与（`memo` 欄ではなく専用フィールド or リンク付きカードとして設計）
- しおり閲覧ページにも同リンクを表示（同行者全員が見る = インプレッション×人数）
- 「PR」表記を添える（ステマ規制対応）
- 収益試算（保守的）: 月間AI生成100件 → 宿リンククリック30% → 予約転換5件 × 平均宿泊¥50,000 × 1% = **月¥2,500前後**。ゼロコストなので全額が黒字
- 上限と悲観ケース: 「コストゼロ」は無料枠の範囲内が前提。Cloudflare Workers Free は**10万リクエスト/日**（超過時は Error 1027。挙動はルートの fail mode 設定に依存し，fail-closed ならエラーページで閲覧も止まり，fail-open なら Worker がスキップされる），Gemini 無料枠は **500生成/日**（旧 3.1 Flash-Lite の実測値。現行既定の 3.5 Flash-Lite の RPD は AI Studio で要確認，超過時は 429 で生成のみ停止）。想定規模では到達しないが，バズ等で超えた場合は Workers Paid（$5/月〜）と Gemini 有料化（3.5 Flash-Lite で1生成約¥0.5）へ切り替える。その悲観ケースでも月300生成で **$5 + ¥150 未満**であり赤字リスクは限定的

### Stage 2: MCPサーバー無料公開 = マーケティング施策

- 課金せず集客・話題性に全振り（原価ほぼゼロ。§2.1の課金はいつでも後付け可）
- MCP経由で作られたしおりにもアフィリエイトリンクは載る → **MCPの利用がそのままStage 1の収益源を太らせる**
- 公開と同時に Zenn/note で実装記事を出す（後述）

### Stage 3（需要実証後・任意）: 直販に踏み込む場合

- 第一候補: **プレミアムしおり買い切り**（¥300/冊: 写真枠・保存期間延長・日数上限解放など）。旅行は単発イベントなのでサブスクより心理的に売りやすく，資金決済法も対象外（特定機能の対価であり前払残高ではない）
- 特商法表記（氏名・住所）が必要になる。回避したければバーチャルオフィス（月額¥500〜）か，MCPマーケットプレイス側での課金に寄せる
- **判断基準: Stage 1-2 で月間しおり作成数が安定して3桁を超えてから**。それ以下なら直販の固定的な手間が見合わない

### ウォッチ枠

- Cloudflare Monetization Gateway の一般提供と日本円対応（半年ごとに再確認）
- MCPize の事業継続性・規約（seller of record の明文）

## 5. マーケティング

### 5.1 プロダクト内バイラルループ（最重要・広告費ゼロ）

Tabiji は**共有されて初めて完成する**プロダクト。1人の幹事が作ると同行者全員（2〜10人）がURLを受け取る構造自体が配布網。

- しおり閲覧ページの末尾に控えめな「このしおりは Tabiji で作られました → 自分も作る」CTA
- **OGP画像の自動生成**（タイトル・日程・行き先入り）。LINEやXでURLを共有した瞬間の見栄えが実質の広告。優先度高
- 旅行後も残る「思い出のページ」としての再訪 → 次の旅行でまた使う循環

### 5.2 コンテンツ・SEO: 公開テンプレートギャラリー

- 「京都 2泊3日 モデルコース」等の**公開テンプレートしおり**を用意し，検索流入の受け皿にする（現状しおりはUUID共有のみでSEO面が皆無）
- テンプレートから「自分用に複製 → AIで人数・日程に合わせて調整」の導線を引くと，SEO → AI機能 → 共有ループが一本に繋がる
- テンプレート自体もAIで量産できる（行き先×季節×日数のマトリクス）

### 5.3 話題化: MCP対応を「記事になるネタ」として使う

- 「旅のしおりアプリをMCP対応させて，Claudeに旅行計画から登録までやらせた話」は Zenn/note/X の個人開発界隈で確実に読まれる題材。**機能そのものより記事の集客力が主目的**
- Anthropic のコネクタディレクトリ等，MCPクライアント側の一覧への掲載を狙う（無料の露出枠）
- Product Hunt / Hacker News は英語圏向けだが，MCP文脈なら刺さる可能性あり

### 5.4 季節運用

- 需要ピークは GW前（3-4月）・夏休み前（6-7月）・年末年始前（11-12月）。テンプレート公開や記事投稿はピークの1〜2ヶ月前に合わせる

### 5.5 ターゲット像

- 主役は**グループ旅行の幹事**（友人グループ・家族旅行の計画係）。「計画の手間を減らしたい，でも共有はきれいにしたい」人
- 幹事1人を獲得すると閲覧者がn人ついてくる。訴求は常に幹事向けに書く

## 6. 検証の順序とKPI

| 段階 | 見るもの | 次に進む条件 |
|---|---|---|
| Stage 0 | AI生成数/週，生成→登録の転換率 | 継続利用がある |
| Stage 1 | アフィリエイトのクリック率・成約数 | 収益が発生する（額は問わない） |
| Stage 2 | MCP経由の作成数，記事からの流入 | — （常設） |
| Stage 3 | 月間しおり作成数 | 安定して3桁超え，かつ特商法表記を許容できる |
