# 画面定義

## 画面遷移フロー

```mermaid
flowchart TD
    Start([ユーザー訪問]) --> Top[トップ画面<br/>/]

    Top -->|しおりを作るボタン| Create[作成・編集画面<br/>/create<br/>mode: create]

    Create -->|入力| CreateForm{共通フォーム}
    CreateForm -->|タイトル入力| CreateForm
    CreateForm -->|概要追加| CreateForm
    CreateForm -->|行程追加| CreateForm
    CreateForm -->|合言葉設定| CreateForm
    CreateForm -->|完了ボタン| Submit[サーバーへ送信<br/>POST /api/shiori]

    Submit -->|保存成功| View[表示画面<br/>/i/:id]
    Submit -->|エラー| CreateForm

    View -->|URLコピーボタン| Copy[クリップボードにコピー]
    View -->|編集ボタン| AuthCheck{合言葉設定あり?}

    AuthCheck -->|なし| Edit[作成・編集画面<br/>/i/:id/edit<br/>mode: edit]
    AuthCheck -->|あり| Password[合言葉入力モーダル]

    Password -->|認証成功| Edit
    Password -->|認証失敗| View

    Edit -->|入力| EditForm{共通フォーム<br/>既存データ読み込み}
    EditForm -->|更新ボタン| Update[サーバーへ送信<br/>PUT /api/shiori/:id]
    Update -->|成功| View
    Update -->|エラー| EditForm
    EditForm -->|キャンセル| View

    style Top fill:#e1f5ff
    style Create fill:#fff4e1
    style View fill:#e8f5e9
    style Edit fill:#fff4e1
```

## 画面一覧

| 画面名 | パス | 説明 |
|--------|------|------|
| トップ画面 | `/` | サービス説明とLP |
| 作成・編集画面 | `/create` または `/i/[id]/edit` | しおりの新規作成・編集（共通フォーム） |
| 表示画面 | `/i/[id]` | しおりを表示（閲覧専用） |

**補足**: 作成画面と編集画面は**同じフォームコンポーネント**を使用します。これは競合サービス（しおりす、タビカンジ、旅しお）すべてで採用されている標準的なパターンです。

---

## 各画面の詳細

### 1. トップ画面（`/`）

**目的**: サービスの紹介と新規作成への導線

**表示要素**:
- サービス名・キャッチコピー
- サービス説明文
- 「しおりを作る」ボタン（CTA）
- サンプル画像（任意）

**アクション**:
- 「しおりを作る」ボタン → `/create` へ遷移

---

### 2. 作成・編集画面（`/create` または `/i/[id]/edit`）

**目的**: しおりの新規作成または既存しおりの編集

**画面の違い**:

| 項目 | 作成モード (`/create`) | 編集モード (`/i/[id]/edit`) |
|------|---------------------|--------------------------|
| ページタイトル | 「しおりを作る」 | 「しおりを編集」 |
| フォーム初期値 | 空欄 | 既存データを表示 |
| 送信ボタン | 「完了」 | 「更新」 |
| キャンセルボタン | なし | 「キャンセル」（`/i/[id]` へ戻る） |
| 合言葉入力 | 任意で設定 | 事前に認証済み |

**入力セクション**:

#### タイトルセクション
- しおりのタイトル（テキスト入力、必須）

#### 概要セクション
- **[概要を追加]** ボタン → 新しい概要項目を追加
- 各概要項目:
  - タイトル（例: 旅費、持ち物）
  - 内容（テキストエリア）
  - 削除ボタン

#### 行程セクション
- **[行程を追加]** ボタン → 新しい行程を追加
- 各行程項目:
  - 日付（日付ピッカー）
  - 日数（任意、数値入力: 1日目、2日目など）
  - 時間（時刻ピッカー）
  - タイトル（場所名・イベント名）
  - 交通手段（選択式）
    - 徒歩 / 電車 / バス / 飛行機 / 車 / 船 / 自転車
  - 補足（テキストエリア、任意）
  - 削除ボタン

#### 合言葉セクション（作成モードのみ）
- 合言葉（パスワード入力、任意）
- 説明文: 「編集時に必要です。設定しない場合は誰でも編集可能になります」

**アクション**:
- **作成モード**: 「完了」ボタン → サーバーへ送信（POST `/api/shiori`） → `/i/[id]` へ遷移
- **編集モード**: 「更新」ボタン → サーバーへ送信（PUT `/api/shiori/[id]`） → `/i/[id]` へ遷移
- **編集モード**: 「キャンセル」ボタン → `/i/[id]` へ戻る
- バリデーションエラー時はエラーメッセージ表示

**実装方針**:
- 共通の`ShioriForm`コンポーネントを使用し、`mode`プロパティで動作を切り替える
- コード重複を避け、保守性を高める

---

### 3. 表示画面（`/i/[id]`）

**目的**: 作成したしおりを表示・共有

**表示要素**:

#### ヘッダー
- しおりのタイトル

#### 概要セクション
- タイトルと内容のリスト表示

#### 行程セクション（タイムライン形式）
- 日付・日数（1日目、2日目など）
- 時間
- 場所・イベント名
- 交通手段アイコン
- 補足情報

#### アクション
- **[URLをコピー]** ボタン → クリップボードにコピー
- **[編集]** ボタン → 合言葉入力モーダルまたは `/i/[id]/edit` へ遷移

**合言葉入力モーダル** (合言葉が設定されている場合):
- 合言葉入力フォーム
- [確認] ボタン
- [キャンセル] ボタン
- 認証成功 → `/i/[id]/edit` へ遷移
- 認証失敗 → エラーメッセージ表示

## UI/UX方針

### モバイルファースト
- スマホ幅固定デザイン（max-width: 480px）
- タップしやすいボタンサイズ（最低44x44px）
- PC表示では中央配置

### タイムライン表示
- 縦方向レイアウト
- 時系列に沿った表示
- 交通手段アイコンを見やすく配置
- 視覚的に美しいデザイン

### 直感的な操作
- 項目の追加・削除が簡単
- リアルタイムプレビュー（検討中）
- エラーメッセージは分かりやすく
