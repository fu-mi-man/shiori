## 1. MVP機能（Phase 1）

ファーストリリースで実装する必須機能。多言語対応の設計は最初から採用し、実装は日本語のみ。

### 1. しおり作成機能

**機能概要**: 旅行のしおりを新規作成する

**入力項目**:

| 項目 | 必須 | 説明 |
|------|------|------|
| タイトル | ✅ | しおりのタイトル（例: 「沖縄旅行 2025年3月」） |
| 概要 | 任意・複数可 | タイトル + 内容（例: 旅費、持ち物、宿泊先など、内容は**最大500文字**） |
| 行程 | 任意・複数可 | 日付、日数、時間、タイトル、交通手段、補足 |
| 合言葉 | 任意 | 編集時の認証用パスワード |

**行程の詳細項目**（すべて任意）:
- 日付（未定でもOK）
- 日数（1日目、2日目など、**MVPは最大10日**）
- 時間
- タイトル（場所名、イベント名）
- 交通手段（徒歩/電車/バス/飛行機/車/船/自転車/タクシー/ケーブルカー）
- 補足（詳細情報、**最大200文字**）

> **設計方針**: 必須項目は最小限に。行程さん作者の教訓「必須項目を減らす → しおり完成まで到達する人数を増やす」「エラーを出さない設計」に倣う。

**出力**:
- 一意のID（UUID）を生成
- 共有URL（`/i/[id]`）を発行

---

### 2. しおり表示機能

**機能概要**: 作成したしおりを閲覧する

**表示形式**:
- **タイムライン形式**: 時系列に沿った縦方向レイアウト
- **交通手段アイコン**: Lucideアイコンで視覚的に表示
- **日数表示**: 1日目、2日目などをサポート（MVPは最大10日、Phase 2以降で最大30日に拡張検討）
- **セクション分離**: 概要セクションと行程セクションを明確に分離
- **日数タブナビゲーション**: 行程上部に「全日 / 1日目 / 2日目 / ...」タブを横スクロールで表示。デフォルトは「全日」を選択（全日程を縦スクロールで一覧表示）。各日タブではその日の行程のみ表示
- **長文の折りたたみ**: 概要の内容・行程の補足は2行で切り詰め、「もっと見る / 閉じる」トグルで展開・折りたたみ

**閲覧権限**:
- URLを知っている人は誰でも閲覧可能
- 認証不要

---

### 3. しおり編集機能

**機能概要**: 既存のしおりを編集する

**編集権限**:
- 合言葉が設定されている場合: 合言葉を入力した人のみ編集可能
- 合言葉が設定されていない場合: 誰でも編集可能

**編集内容**:
- 作成時と同じ項目を編集可能
- 保存時に更新

**認証方式**:
- 合言葉はbcryptでハッシュ化して保存
- 編集時に照合

---

### 4. URL共有機能

**機能概要**: しおりのURLを共有する

**実装内容**:
- 一意のURL生成（例: `https://shiori.app/i/abc123`）
- 「URLをコピー」ボタン → クリップボードにコピー
- コピー成功時にトースト通知

---

### 5. 自動削除機能

**機能概要**: 一定期間アクセスがないしおりを自動削除

**削除条件**:
- 最終アクセスから3ヶ月後に自動削除
- 課金済み（`is_premium = true`）のしおりは対象外
- データの無期限保持を防ぐ

**実装方法**:
- Vercel Cron Jobsで定期実行
- `last_accessed_at`を毎回更新
- 3ヶ月以上古い無料しおりを削除

**削除通知**:
- メール通知なし（アカウントレス設計のため）
- 表示画面に「このしおりは○月○日に削除されます」を表示

## 2. Phase 2機能

ユーザーフィードバックを集め、サービスを改善するフェーズ。

### 1. フィードバック掲示板

**機能概要**: ユーザーが機能リクエストや改善提案を投稿できる掲示板

**ユーザーの利点**:
- 欲しい機能をリクエストできる
- 他のユーザーのリクエストに賛同できる
- サービスの改善に参加できる

**掲示板の仕様**:
- スレッド形式（リクエスト → コメント）
- 「賛成」ボタンのみ（反対なし → 対立を避け建設的な雰囲気を維持）
- 匿名投稿OK（アカウント不要）
- 多言語対応（日本語・英語で投稿可能）
- 投票数でソート可能

**モデレーション**:
- OpenAI Moderation API（無料）で不適切投稿を自動フィルタ
- レートリミット（1日3件まで等）でスパム防止

**運営側のメリット**:
- ユーザーの本当のニーズが分かる
- 開発優先度を決めやすい
- 行程さん作者が言う「想定外の価値」を発見できる

---

### 2. 多言語対応（英語）

**機能概要**: 英語でサービスを利用可能にする

**対応範囲**:
- UI全体の英語化
- 掲示板への英語投稿
- 民泊ゲスト向け利用

**技術実装**:
- Next.js 16のi18n機能を活用
- `locales/`ディレクトリに翻訳ファイルを配置
- 言語切り替えUI

---

### 3. テンプレート機能

**機能概要**: よくある旅行パターンのテンプレートを提供

**テンプレート例**:
- 国内1泊2日
- 国内2泊3日
- 海外3泊4日
- 日帰り旅行

**ユーザーの利点**:
- ゼロから作らず、テンプレートを選んで項目を埋めるだけで完成
- 作成時間を大幅に短縮 → 共有までの時間も短縮
- 旅行の行程の漏れを防げる

---

### 4. カラーテーマ選択機能

**機能概要**: しおりの配色テーマを選択できる

**テーマ例**:
- ブルー系（爽やか・海）
- ピンク系（かわいい・華やか）
- グリーン系（自然・リラックス）
- ダーク系（シック・大人）

**技術実装**:
- Tailwind CSSのテーマ変数を切り替え
- データベースに選択したテーマを保存

---

### 5. ヘッダーカスタマイズ

**機能概要**: しおりのヘッダーに画像やアイコンを設定できる

**実装方法**:
- あらかじめ用意した画像・アイコンから選択式（Phase 2）
- 画像アップロードは需要次第でPhase 3以降

**ユーザーの利点**:
- 視覚的インパクト
- 旅行のイメージを表現できる
- 共有時に「おっ」と思わせる

---

### 6. AI行程作成機能

**機能概要**: 目的地と日数を入力するだけで、AIがおすすめルートを提案

**ユーザーの利点**:
- 「沖縄 2泊3日」と入力 → おすすめルートが自動生成
- 旅行計画の手間を大幅に削減
- 編集可能な形でしおりに反映

**技術実装**:
- OpenAI API または Claude API
- プロンプトで行程フォーマットを指定
- 生成結果をしおりデータに変換

---

### 7. PDF出力機能

**機能概要**: 作成したしおりをPDF形式でダウンロード

**ユーザーの利点**:
- 印刷して紙で持ち歩ける
- 電波が届かない場所でもオフラインで見れる
- 記念として保存できる

**技術実装**:
- サーバーサイドでPDF生成
- 無料ユーザー: 無制限（レートリミットのみ）

---

## 3. Phase 3機能（需要次第）

掲示板のフィードバックを基に、需要があれば実装する機能。

### 1. 写真挿入機能

**機能概要**: 概要や行程に写真を挿入できる

**検討理由**:
- 観光地の写真 → Googleで検索すれば出てくる
- ホテルの外観 → 住所があれば十分
- 思い出として → 旅行後に別のアルバムで管理する人が多い

**実装方針**:
- Cloudflare R2（無料枠10GB）を使用
- Next.js Image Optimizationで最適化

---

### 2. 地図表示機能

**機能概要**: 行程の場所を地図上に表示

**検討理由**:
- Google Maps APIは従量課金
- ユーザーが本当に必要としているか要確認

**実装方針**:
- Google Maps APIまたはMapbox
- 行程の位置情報から自動プロット

---

### 3. 天気予報連携

**機能概要**: 旅行日程の天気予報を自動表示

**検討理由**:
- 天気予報アプリで確認する人が多い
- API連携のメンテナンスコスト

**実装方針**:
- OpenWeather API（無料枠あり）
- 行程の日付と場所から自動取得

---

### 4. アジア言語対応

**機能概要**: 韓国語、中国語（簡体字・繁体字）に対応

**実装タイミング**:
- 英語版の利用状況を見て判断
- 掲示板でのリクエスト数を参考に

---

### 5. 簡易翻訳機能

**機能概要**: しおり全体を他言語に機械翻訳

**ユースケース**:
- 日本人が作ったしおりを訪日外国人ゲストに共有
- 宿泊事業者が多言語対応を簡単に実現

**技術実装**:
- Google Translate API または DeepL API
- しおり表示画面に「Translate」ボタン


## 4. マネタイズ機能（Phase 3）

### 1. フェーズ別方針

- **MVP〜Phase 2**: 完全無料（Vercel Hobby、非商用利用）
- **Phase 3**: Vercel Pro ($20/月) に移行、収益化開始

### 2. 広告（AdSense）

- **配置**: しおり表示画面の下部（コンテンツを邪魔しない位置）
- **対象**: 無料ユーザーのみ
- **注意**: Vercel Pro必須（商用利用）

### 3. 有料プラン（検討中）

> **⚠️ 未定**: マネタイズ方針を再検討中。「永久保存課金（買い切り）」は誤解を招く文言のため廃止。代替案は未定。

### 4. 技術実装

- アカウント不要（しおりIDに`is_premium`フラグを持つ）
- 決済: **Stripe**
  - クレジットカード、PayPay、Apple Pay、Google Pay等
  - グローバル対応（135通貨）でインバウンド観光客にも対応
- 課金者メールアドレス: 領収書送付用に取得


## 5. 実装しない機能

| 機能 | 理由 |
|------|------|
| ドラッグ&ドロップ並び替え | 削除→追加で代替可能、実装コスト高 |
| 外部サービス連携（乗換案内など） | 実装コスト高、ユーザーが自分で検索して入力する方がシンプル |
| アカウント機能 | サービスのコンセプト（シンプルさ）に反する |
| コメント・チャット機能 | スコープ拡大、LINEなど既存ツールで代替可能 |
| 「next」表示（現在時刻連動） | 直感的に理解できない機能は逆効果（行程さんで不評） |
| 割り勘連携 | 旅のしおりの本質から外れる |
| 位置情報共有 | プライバシー配慮、実装コスト高 |

## 7. 非機能要件

### 1. UI/UX

- **モバイルファースト設計**（必須）
  - スマホでの使いやすさを最優先
  - タップしやすいボタンサイズ（最低44x44px）
  - スクロールのスムーズさ
- **タイムライン表示の強化**（必須）
  - 時系列に沿った縦方向レイアウト
  - 移動手段アイコンを見やすく配置
  - 時間・日付の明瞭な表示
- **スマホ幅固定デザイン**
  - max-width: 480px程度
  - PC表示でも中央に配置
- **シンプルで直感的なUI**

### 2. アクセシビリティ

- セマンティックHTML
- キーボードナビゲーション対応
- スクリーンリーダー対応
- コントラスト比の確保

### 3. ブラウザ対応

- Chrome（最新版）
- Safari（最新版）
- Firefox（最新版）
- Edge（最新版）

### 4. セキュリティ

- 合言葉はbcryptでハッシュ化して保存
- SQLインジェクション対策（Drizzle ORMのパラメータバインディング）
- XSS対策（Reactのエスケープ + CSP）
- CSRF対策（Next.jsのデフォルト機能を活用）

### 5. パフォーマンス

- ページ読み込み: 3秒以内
- API応答時間: 1秒以内
- Lighthouse Score: 90以上（目標）
- 即時アクセス前提（移動中でも待たずに表示される軽量・高速構成）

### 6. 多言語対応設計

- i18n設計をMVPから採用
- 翻訳ファイルの分離（`locales/`）
- 日付・時刻フォーマットのローカライズ
- RTL対応は将来検討（アラビア語等）

### 7. 基本方針

- アカウント登録不要
- メールアドレス不要
- 完全無料（Phase 1-2）
